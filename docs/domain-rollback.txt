QUICKEST RETURN TO THE OLD WEBSITE (after Netlify HTTPS is working)
1. Replace the repository's _redirects file with the single rule in docs/emergency-weebly-redirects.txt.
2. Commit and push to main; wait for Netlify to show Published.
3. Test the main domain in a private browser window. Every URL will temporarily send visitors to the old Weebly homepage. Its own navigation, historical pages, and newsletter remain on Weebly.
4. To undo this emergency mode, restore _redirects from the migration commit 124ae1c and redeploy.
This keeps the main domain on Netlify and therefore avoids another DNS wait. It does not repair a missing Netlify TLS certificate or a Netlify service outage.

FULL RETURN TO WEEBLY HOSTING
1. Keep the original Weebly site and its plan active. Do not delete it, reset DNS, change nameservers, or cancel the domain registration.
2. In the original site's editor, Settings > General > Site Address > Change, connect www.mastersargentina.org again. Choose connect, not a domain transfer or paid new domain. Publish. The connection may automatically update Weebly-managed DNS; inspect the records afterward.
3. Restore the website DNS records: @ A 199.34.228.68; www A 199.34.228.68. Replace the www CNAME rather than leaving conflicting A/CNAME records. If Weebly's reconnect flow provides an updated required IP, use the newly displayed IP consistently for @ and www and document that change.
4. Leave all email/MX, Brevo/DKIM/DMARC, verification, mail, wildcard, nameserver, and conference records unchanged. Never use Reset DNS records.
5. Test root and www over HTTPS, the home page, historical pages, newsletter and contact forms. Verify the Weebly dashboard shows the intended published address. Reconnecting the original site to the main domain may detach old.mastersargentina.org; the same original content then lives at the main domain. Keep the archive DNS entries until their handling has been checked.
6. DNS records originally had TTL 14400 seconds (4 hours). The Weebly editor did not expose a TTL field. Some visitors may retain the previous route for hours; rollback is not instantaneous. Existing cached permanent redirects can also outlive the DNS change, so do not remove the archive prematurely.
